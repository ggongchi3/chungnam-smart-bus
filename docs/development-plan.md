# 초기 개발 기준안 v0.1

작성일: 2026-10-25. 사용자의 요청에 따라 시연 범위·기술 스택·공통 데이터·API 연동 규칙을 구체화한 프로젝트 내부 기준안이다. 실제 팀원들의 검토·합의가 완료되었다는 기록은 아니다. 아래 기준으로 작업을 시작하고 변경 사항은 공통 문서와 PR에 함께 반영한다.

사진의 서비스 기능을 구현하기 위한 기술 선택·시연 규모·처리 정책은 추가 설계 제안이다. 실제 충남의 노선·운행 시각·환승 조건이나 외부 API 제공 범위를 확인한 결과로 해석하지 않는다. 실행 코드와 설치·실행 명령은 아직 없으며, 이번 변경의 산출물은 개발 기준 문서다.

## 1. 시연 범위

첫 시제품은 데스크톱 Chrome에서 사용하는 하나의 웹 앱으로 만든다. 현재 정류장은 설정값 `demo-stop-001`로 고정하고, 합성 정류장 5개·단방향 노선 2개·목적지 3개를 사용한다. 화면·음성·인쇄물에 `시연 데이터 · 실제 운행 정보 아님`을 표시한다.

| 항목 | v0.1 구현 기준 |
| --- | --- |
| 화면 흐름 | 시작 → 목적지 검색/주요 장소 → 경로 선택 → 상세 이동 안내 → 인쇄용 미리보기 |
| 목적지 | 병원·시장·터미널 3개. 직접 검색과 큰 분류 버튼을 함께 제공한다 |
| 경로 | 직통 및 최대 1회 환승. 확인한 합성 경유 순서·도보 연결·환승 연결만 사용한다 |
| 경로 정렬 | 환승 수 → 버스로 지나는 정류장 수 합계 → 경로 식별자 순. 최대 3개를 반환한다. 소요시간이 없는 경로를 최단시간 경로라고 표시하지 않는다 |
| 운행 정보 | 합성 도착 정보, 운행 상태, 시간표 변경·결행·우회·미수신·오래된 정보 시나리오 |
| 이동 안내 | 버스 번호, 승차·하차 정류장, 정류장 수, 도보·환승 순서 |
| 출력 | A4 세로, 여백 15mm, 본문 16pt를 시작 기준으로 삼고 브라우저 인쇄/미리보기에서 조정한다 |
| 음성 | 사용자가 누르면 한국어 안내를 재생하고 중지할 수 있다. 지원 음성이 없거나 실패하면 텍스트 안내를 유지한다 |
| 완료 기준 | 아래 8개 상태를 시연하고, 화면·음성·인쇄의 경로 식별자와 버전이 일치한다 |

시연 상태는 정상 직통, 정상 1회 환승, 목적지 결과 없음, 도착 정보 미수신, 오래된 정보, 시간표 변경, 결행, 우회로 정한다. 여기에 AI 실패·음성 미지원·인쇄 취소를 대체 동작 점검 항목으로 추가한다. 상태 전환 방법은 백엔드가 제공하는 시연 설정으로 관리하며 운영 사용자용 기능으로 노출하지 않는다.

실제 교통 데이터 전환과 실제 키오스크·전용 프린터 연결은 후속 단계다. 공식 출처·지역 범위·키·호출 제한·갱신 시각·환승 연결을 확인하기 전까지 `dataMode=demo`를 유지한다.

## 2. 기술 스택

| 영역 | 선정 기술 | 선택 이유·관리 기준 | 대표 관리자 |
| --- | --- | --- | --- |
| 프론트엔드 | React + TypeScript + Vite | A/B가 한 앱의 컴포넌트와 타입을 공유한다. npm과 package-lock.json으로 의존성을 관리한다 | A |
| 스타일·상태 | CSS Modules + CSS 변수, React Context + useReducer | 디자인 기준을 공통 변수로 관리하고 5단계 화면과 선택 상태를 한곳에서 관리한다 | A, 디자인 기준은 디자인 |
| API 클라이언트 | 브라우저 fetch + AbortController | `frontend/src/shared/api/`에서 응답·오류·제한시간을 처리한다 | A |
| 백엔드 | Python + FastAPI + Uvicorn | 교통 서비스와 AI 담당이 같은 언어를 쓰고 Pydantic으로 입출력을 검증한다 | 백엔드 |
| 데이터 저장 | SQLite + SQLAlchemy | 시연 정류장·목적지·노선·검색 스냅샷을 파일 DB로 관리한다 | 백엔드 |
| AI 연동 | Python 함수 호출, 규칙 기반 목적지 기준선 + 허용 템플릿 선택 | 첫 시연은 외부 모델 호출 없이 동작하도록 만든다. 규칙 기준선을 학습 모델 추론으로 표현하지 않는다 | AI |
| 음성 | Web Speech API의 speechSynthesis | `ko` 계열 음성의 실제 제공 여부를 실행 환경에서 확인한다. 선택된 음성의 지역·네트워크 의존성은 기기에서 검증한다 | B |
| 인쇄 | HTML/CSS 인쇄 레이아웃 + window.print() | 브라우저 인쇄 대화상자를 사용한다. 종이 출력 성공을 서버가 확인했다고 표시하지 않는다 | B |
| 디자인 | Figma, SVG 아이콘, 시스템 글꼴 | 시안과 원본 링크·에셋 출처를 design/에 기록하고 실제 이용 조건을 확인한다 | 디자인 |

정확한 패키지 버전은 첫 코드 생성 시 서로 호환되는 버전을 설치·실행 확인한 뒤 잠금파일에 고정한다. Node.js의 지원 범위는 당시 Vite 공식 요구사항에 맞춘다. 현재 문서만 있는 상태에 작동 확인되지 않은 설치 명령을 추가하지 않는다.

백엔드는 시연용 단일 프로세스를 기준으로 한다. AI는 동일 Python 환경의 논리 모듈로 연결하고 공개 AI 서버를 별도로 배포하지 않는다. 현재 `ai/destination-interpretation/`, `ai/easy-guidance/`는 기술 중립적인 작업 구분이다. Python 패키지를 생성하는 단계에서 각각 `destination_interpretation`, `easy_guidance`로 경로와 참조를 함께 정리한다.

SQLite 실행 파일은 향후 `backend/.local/`에 생성하고 Git에서 제외한다. 합성 초기 데이터의 원본은 `backend/integrations/`에 버전 관리하고 DB에 적재하는 방식으로 준비한다. 아직 데이터 파일·DB·패키지 설정을 생성하지 않았다.

## 3. 공통 시연 데이터

다음 이름·ID·연결은 모두 합성 설정이다. 실제 지명·노선이나 공식 교통 정보가 아니다. 좌표·거리·소요시간은 검증 자료가 없으므로 null로 두며 임의의 속도로 계산하지 않는다.

| 정류장 ID | 표시명 |
| --- | --- |
| `demo-stop-001` | 시연 출발 정류장 |
| `demo-stop-002` | 시연 시장 앞 정류장 |
| `demo-stop-003` | 시연 병원 앞 정류장 |
| `demo-stop-004` | 시연 마을 정류장 |
| `demo-stop-005` | 시연 터미널 앞 정류장 |

| 노선 ID·표시명 | 단방향 경유 순서 |
| --- | --- |
| `demo-route-001` · 시연 1번 | demo-stop-001 → demo-stop-002 → demo-stop-003 |
| `demo-route-002` · 시연 2번 | demo-stop-003 → demo-stop-004 → demo-stop-005 |

| 목적지 ID | 표시명·분류 | 도착 정류장 | 등록 별칭 |
| --- | --- | --- | --- |
| `demo-destination-001` | 시연 병원 · hospital | demo-stop-003 | 병원, 큰 병원, 시연 큰 병원 |
| `demo-destination-002` | 시연 시장 · market | demo-stop-002 | 시장, 전통시장 |
| `demo-destination-003` | 시연 터미널 · terminal | demo-stop-005 | 터미널, 버스터미널 |

출발 정류장 001에서 시장은 1정류장, 병원은 2정류장을 이동한다. 터미널은 1번 버스로 003까지 이동한 뒤 같은 합성 정류장에서 2번으로 1회 환승한다. 이 환승 연결은 시연 데이터에 명시적으로 등록한다. 실제 연동 시 정류장 이름이나 좌표가 같다는 이유만으로 환승 가능하다고 판단하지 않는다.

각 목적지는 해당 도착 정류장에서 목적지까지의 합성 도보 연결을 가진다. 도보 연결의 존재는 시연 설정이고 거리·시간은 미제공 상태로 둔다. 전체 이동시간도 null로 표시한다. 돌아오는 방향과 미래 출발 시간의 경로 조회는 후속 범위다.

## 4. 공통 데이터 규칙

| 항목 | 결정 |
| --- | --- |
| ID·필드명 | ID는 문자열, 필드명은 lowerCamelCase. 정류장/목적지/노선/경로 선택 ID를 구분한다 |
| 단위 | 시간 간격은 초, 거리는 미터. 정류장 수는 출발을 제외하고 하차를 포함한다 |
| 시각 | 시간대 오프셋이 있는 ISO 8601. 서버는 UTC로 비교하고 화면은 Asia/Seoul로 표시한다 |
| 미확인 값 | null + 상태 필드. 0분·현재 시각·정상 운행으로 채우지 않는다 |
| 경로 구간 | 순서 있는 bus / walk / transfer 배열. segmentId는 같은 스냅샷 안에서 고유하다 |
| 경로 상태 | ready / recheck_required / unavailable. 도착 정보 미수신과 확인된 결행을 구분한다 |
| 검색 유효기간 | 생성 후 10분. 응답에 expiresAt을 제공한다. 만료 시 다시 검색한다 |
| 경로 버전 | 경유 순서·연결·경로에 영향을 주는 변경이 생기면 갱신한다. 단순 도착 예상 값 갱신으로는 바꾸지 않는다 |
| A→B 전달 | originStationId, destinationId, routeSearchId, routeOptionId, routeSnapshotVersion, dataMode |
| 스키마 관리 | 현재는 api-contract.md가 기준이다. 코드 생성 후 백엔드 Pydantic/OpenAPI와 TypeScript 타입을 같은 PR에서 맞춘다 |

A는 공통 React 상태에 선택 객체를 저장하고 B는 식별자로 상세/실시간 정보를 조회한다. 새로고침으로 상태가 사라지면 현재 정류장을 유지한 시작 화면으로 이동한다. 검색어·사용자의 이용 이력은 브라우저에 영구 저장하지 않는다.

## 5. API·상태 처리 기준

구체적인 요청·응답은 [api-contract.md](api-contract.md)를 따른다. 이 기준은 우리 서비스의 내부 계약이며 외부 교통 API의 제공 기능을 뜻하지 않는다.

| 항목 | v0.1 기준 |
| --- | --- |
| 공개 API | 기존 8개 서비스 API를 /api/v1 아래에 구현한다. 프론트엔드는 백엔드만 호출한다 |
| 응답 봉투 | data / error / meta. 성공이면 error=null, 실패이면 data=null |
| 시간 메타데이터 | generatedAt은 응답 생성, sourceUpdatedAt은 원천 갱신, fetchedAt은 서버 수집. 서로 대체하지 않는다 |
| 목적지 검색 | query는 앞뒤 공백 제거 후 최대 100자, AI text는 1~200자. 시연은 전체 3개 후보를 반환하므로 페이지 분할을 쓰지 않는다 |
| 현재 출발 | departAt은 필수이며 서버 시각과 차이가 절댓값 120초 이내인 요청만 받는다. 그 밖의 조회는 INVALID_REQUEST |
| 실시간 조회 | 상세 화면 진입 시 1회, 화면이 활성화된 동안 30초마다. 화면을 벗어나면 중지한다 |
| 최신성 | 도착·운행 변경 자료의 sourceUpdatedAt이 있고 서버 기준 0~90초 전이면 fresh, 90초 초과면 stale, 없거나 미래이면 unknown |
| 기준의 적용 범위 | 90초는 시연용 내부 정책이다. 실제 제공자 적용 시 호출 제한·갱신 정책을 확인하여 다시 정한다. 정적 노선 자료는 데이터 버전으로 별도 관리한다 |
| 클라이언트 제한시간 | 5초. GET의 일시적 연결 실패/5xx만 1초 후 1회 재시도한다. 4xx와 POST는 자동 재시도하지 않는다 |
| AI 제한시간 | 결과 채택 예산 1초. 실패·시간초과·허용 목록 위반이면 일반 검색/고정 템플릿으로 대체한다 |
| 인증·연결 | 로컬 시연은 로그인 없이 사용한다. 개발 포트는 프론트 5173·백엔드 8000을 사용하고 로컬 프론트 주소만 CORS에 허용한다. 공개 배포 주소·운영 인증은 후속 결정이다 |

공통 오류는 400 INVALID_REQUEST, 404 NOT_FOUND, 409 ROUTE_VERSION_CHANGED 또는 ROUTE_UNAVAILABLE, 410 ROUTE_SEARCH_EXPIRED, 503 TRANSPORT_DATA_UNAVAILABLE로 정한다. 검색 결과 없음은 200과 빈 배열, 실시간 부분 실패는 200과 항목별 unavailable/unknown 상태로 표현한다. FastAPI의 기본 입력 검증 오류도 서비스 구현 시 400과 공통 오류 봉투로 변환한다.

프론트엔드는 stale/unknown인 도착 수치를 현재 예측처럼 보여주지 않는다. 운행 변경 조회 실패를 `변경 없음`으로 표시하지 않는다. AI 실패만으로 경로 API를 실패 처리하지 않는다.

## 6. AI 담당의 구현 기준 — 추가 제안

첫 기준선은 공백 정규화, 등록 이름·별칭 포함 여부, 장소 분류 표현을 이용해 등록된 후보 ID를 찾는다. 후보가 한 개면 matched, 여러 개면 needs_confirmation, 없으면 no_match로 반환하며 어느 경우든 사용자가 후보를 확인하고 선택한다. 일반적인 `병원` 표현으로 실제 특정 병원을 추정하지 않는다. 이 시연에서 병원 후보가 하나인 것은 위 합성 목록의 구성 때문이다.

백엔드는 AI 후보가 allowedDestinations 안에 있는지 다시 검증한다. 안내는 등록된 구간 순서와 허용된 templateId만 받으며 사실 값은 서버가 채운다. AI는 정류장·노선·정류장 수·시간·환승 연결을 추가하거나 바꾸지 않는다.

모델 도입 실험은 이 기준선·입출력 계약을 대체하지 않고 별도 비교 대상으로 진행한다. 외부 LLM 제공자·모델·키·요금·품질 목표는 아직 선정하지 않았다. 모델 호출을 첫 시연의 필수 의존성으로 만들지 않는다. 평가 자료에는 표현 변형, 동명/모호한 후보, 후보 없음, 목록 밖 ID, 잘못된 구간 순서, AI 실패를 포함한다. 아직 측정하지 않은 정확도를 기재하지 않는다.

## 7. 화면·음성·출력 기준

| 항목 | 시작 기준 |
| --- | --- |
| 화면 글자 | 본문 24px 이상, 제목 32px 이상, 줄 간격 1.5. 글자 크기로 정보를 구분하되 색상만으로 상태를 전달하지 않는다 |
| 버튼 | 주요 터치 영역 최소 64×64 CSS px, 주요 요소 간격 16px. 프로젝트의 고령층 UI 목표이며 표준 최소 수치라고 주장하지 않는다 |
| 대비·초점 | 일반 안내 텍스트 대비 4.5:1 이상을 목표로 측정하고 키보드 초점과 읽는 순서를 확인한다 |
| 경로 문구 | 한 단계에 한 행동. 노선·정류장 이름을 생략하지 않고 구간 순서대로 표시한다 |
| 음성 | 데모 안내임을 먼저 알리고 검증된 이동 순서를 읽는다. 재생 전에 이전 읽기를 취소하고 중지 버튼을 제공한다. 한국어 음성의 가용성은 getVoices()와 변경 이벤트로 확인한다 |
| 인쇄 내용 | 시연 표시, 출발·목적지, 승하차·정류장 수·도보·환승, 안내표 생성 시각, 원천 갱신/확인 불가 상태. 변동하는 도착 카운트다운은 종이에 넣지 않는다 |
| 인쇄 허용 | 경로 ready이면 도착 정보 미수신 상태를 명시하고 인쇄할 수 있다. 확인된 결행/이용 불가, 경로 버전 변경, 검색 만료면 재확인/재검색한다 |
| 인쇄 취소 | 상세 또는 인쇄용 화면으로 돌아와 다시 시도할 수 있다. 인쇄 창 종료만으로 `출력 완료`라고 표시하지 않는다 |

출력 전 서버가 경로 버전과 상태를 확인하고 스냅샷을 만든다. 인쇄 대화상자를 연 동안에는 인쇄용 DOM의 내용을 자동 갱신하지 않는다. 긴 안내는 글자를 줄여 억지로 한 장에 넣지 않고 페이지를 나누어 확인한다.

WCAG 2.2의 텍스트 대비 기준 등을 설계 근거로 참고하되, 위 일부 항목을 정했다는 이유로 전체 표준 준수나 인증을 완료했다고 표시하지 않는다.

## 8. 담당자별 시작 산출물과 연동 순서

| 순서 | 담당 | 첫 산출물 | 다음 단계로 넘어갈 기준 |
| --- | --- | --- | --- |
| 1 | 백엔드 + 디자인 | 위 합성 데이터·스키마·5단계 화면/인쇄 시안 | 같은 정류장·목적지·용어·상태를 사용한다 |
| 2 | A | 단일 React 앱·공통 상태/UI·API 클라이언트·검색/선택 화면 | 정해진 A→B 객체로 상세 화면에 진입한다 |
| 3 | 백엔드 + B | API와 상세·실시간·인쇄 UI | 10분 만료, 버전 변경, 미수신/오래됨, 인쇄 취소를 처리한다 |
| 4 | AI + 백엔드 | 목적지 기준선·허용 템플릿·출력 검증·대체 동작 | 목록 밖 ID·잘못된 구간·시간초과가 교통 안내를 바꾸지 않는다 |
| 5 | 전원 | 정상 직통/환승과 상태 시연, 실제 브라우저 인쇄·음성 검토 | 시연 표시와 경로 사실이 화면·음성·인쇄에 일치한다 |

디자인/A/B는 작업 중 병행 검토하고 백엔드·AI는 일반 검색/고정 템플릿부터 연결한다. 외부 교통 연동은 [data-sources.md](data-sources.md)의 출처 확인이 끝난 항목부터 별도 추가한다.

## 9. 확인한 기술 근거

아래 문서는 2026-10-25에 확인했다. 기술의 동작 근거이며 시연 규모·도착 갱신 주기·성능·개발 완료를 입증하는 자료가 아니다. 위 기술 선택과 내부 수치는 이 프로젝트의 설계 판단이다.

- [React 공식 문서 — Build a React app from Scratch](https://react.dev/learn/build-a-react-app-from-scratch): Vite의 React/TypeScript 구성 예시와 직접 구성할 때의 한계를 확인했다. 한정된 브라우저 시연을 위한 선택이다.
- [Vite 공식 문서 — Getting Started](https://vite.dev/guide/): 지원 템플릿과 Node.js 요구사항을 확인했다.
- [FastAPI 공식 문서 — Features](https://fastapi.tiangolo.com/features/): OpenAPI/JSON Schema 기반 명세와 Pydantic 데이터 검증을 확인했다.
- [SQLAlchemy 공식 문서 — Engine Configuration](https://docs.sqlalchemy.org/en/21/core/engines.html): SQLite 파일 DB 연결을 확인했다.
- [MDN — Window.print()](https://developer.mozilla.org/en-US/docs/Web/API/Window/print): 현재 문서의 인쇄 대화상자를 여는 동작을 확인했다.
- [MDN — SpeechSynthesis.getVoices()](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices): 현재 기기에서 사용 가능한 음성 목록을 조회하는 동작을 확인했다. 한국어 음성을 모든 기기에서 제공한다고 보장하지 않는다.
- [W3C — WCAG 2.2, Contrast Minimum](https://www.w3.org/TR/WCAG22/#contrast-minimum): 일반 텍스트 대비 4.5:1 기준과 예외를 확인했다. 64px 버튼 등 자체 목표와 구분한다.
