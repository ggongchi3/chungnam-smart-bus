# 데이터 출처와 확인 사항

이 문서는 필요한 데이터와 조사 상태를 기록한다. 외부 교통 API·공식 교통/인구 통계·해당 이용약관은 이번 설계 작업에서 확인하거나 연동하지 않았다. 기술 문서의 확인 기록은 development-plan.md 9절에 별도로 기록한다. 아래의 `미정`, `확인 필요`는 미확인 상태이며 제공 가능성을 보장하지 않는다. API 키가 필요한지 역시 실제 제공기관 선정 전에는 확정하지 않는다.

## 3. 담당자와 확인 순서

1. 백엔드가 시연할 충남 내 정류장·노선·목적지의 범위를 합의한다. 충남과 대전·세종·충북 자료를 구분한다.
2. 백엔드가 제공기관의 공식 URL, 정확한 자료명/엔드포인트, 확인일, 지원 지역·필드, 인증·호출 제한, 이용조건을 이 문서에 추가한다. 검증 전에는 `확인 필요`를 유지한다.
3. 실제 샘플 응답으로 정류장·노선 ID의 연결, 시간대, 갱신 시각, 미수신 상태, 운행 변경 범위를 확인하고 내부 계약으로 매핑한다. API 키는 문서·예시·시연 데이터에 넣지 않는다.
4. 도보·환승 데이터의 근거를 검증한다. 두 정류장이 가깝다는 이유만으로 환승 가능하다고 확정하지 않는다.
5. A/B는 제공 범위에 맞춰 `정보 없음`, `확인 불가`, `오래된 정보`, `시연 데이터` 상태를 구현한다. AI는 제공되지 않은 교통 사실을 보완하지 않는다.
6. 디자인은 에셋과 글꼴의 출처·라이선스를 기록한다. 사진의 통계나 기대 효과를 발표 자료에 쓰려면 별도의 원출처 확인을 먼저 한다.

## 4. 초기 시연 데이터 정책 — 추가 제안

외부 연동 전에는 `demo-` 접두사의 합성 ID와 `시연 정류장`, `시연 병원`, `시연 노선` 같은 명백한 시연 이름을 사용한다. 시연 데이터의 대표 관리자는 백엔드다. 실제 지명·교통 시각을 추정하여 합성 데이터를 만들지 않는다.

화면·음성·인쇄물에는 `시연 데이터 · 실제 운행 정보 아님`을 식별할 수 있게 표시한다. 정상 경로, 결과 없음, 정보 미수신, 지연, 운행 변경, AI 실패, 인쇄 취소를 시연할 자료를 마련한다. 구체적인 정류장 5개·노선 2개·목적지 3개와 연결은 [development-plan.md](development-plan.md) 3절에 정의했다. 현재 합성 원본은 [backend/integrations/demo-data.json](../backend/integrations/demo-data.json)에 구현되어 있다. 이 원본의 존재나 합성 제공자 테스트가 실제 교통 출처 검증을 뜻하지 않는다.

`dataMode=live`는 제공자를 선정했다는 뜻이 아니라 승인된 실제 데이터 연결을 사용할 때 부여할 내부 모드다. 실제 연결·갱신·출처 검증이 끝나기 전에는 live로 표시하지 않는다. 부분 실패는 데이터별 상태와 시각으로 구분한다.
