# 목적지 표현 해석 — 규칙 기반 기준선

`interpreter.py`의 `interpret(payload)`가 자연어 목적지 표현을 등록 후보 ID에 연결한다. 학습 모델이 아니며 외부 호출이 없다. 입출력은 [contracts/README.md](../contracts/README.md) 1절을 따른다.

## 규칙

1. **정규화**: NFKC, 소문자, 한글·영숫자 외 기호 제거, 공백 정리 후 공백을 없앤 문자열로 비교한다.
2. **검색어 만들기**: 후보마다 이름·별칭 전체(`시연병원`), 합성 접두어 `시연`을 뺀 핵심어(`병원`, `큰병원`), 분류 표현(`CATEGORY_TERMS`)을 검색어로 만든다. 분류 표현은 핵심어에 그 분류어가 들어 있는 후보 **전체**에 연결한다.
3. **더 구체적인 표현 우선**: 입력에서 찾은 표현이 더 긴 표현의 범위 안에 있으면 버린다. `큰 병원`에서는 `큰병원`만 남고 그 안의 `병원`은 버린다.
4. **부정 표현**: 표현 바로 뒤에(조사 허용) `말고·빼고·아니고·아니라·아닌`이 오면 그 후보를 뺀다. `병원 말고 시장` → 시장.
5. **오타 추정**: 정확히 맞는 표현이 하나도 없을 때만, 같은 길이에서 초성·중성·종성 중 1개만 다른 표현을 찾는다(`벙원` → 병원). 이 결과는 후보가 1개여도 `needs_confirmation`이다.
6. **판정**: 정확한 표현으로 찾은 후보가 1개면 `matched`, 여러 개이거나 오타로 추정했으면 `needs_confirmation`, 없으면 `no_match`다. 어느 경우든 사용자가 후보를 확인하고 고른다.

## 분류 표현

| 분류어 | 연결하는 표현 |
| --- | --- |
| 병원 | 병원, 종합병원, 대학병원 |
| 시장 | 시장, 전통시장, 재래시장, 장터, 장보러, 장보기, 장날 |
| 터미널 | 터미널, 버스터미널, 시외버스터미널, 고속버스터미널, 시외버스, 고속버스 |

`의원`·`보건소`처럼 다른 종류의 장소일 수 있는 표현은 넣지 않았다. 표현을 추가할 때는 [evaluation/cases.json](../evaluation/cases.json)에 사례를 함께 추가한다.

## 알려진 한계

- 부정은 표현 바로 뒤의 정해진 단어만 본다. `병원은 안 가고 시장`처럼 다른 형태는 이해하지 못하고 두 후보를 모두 돌려준다.
- 오타는 자모 1개 차이·같은 글자 수만 본다. 글자 누락·추가(`병언원`)나 초성 입력은 연결하지 않는다.
- 자모 1개 차이인 다른 단어(`시정` → 시장)도 오타로 볼 수 있다. 확인 필요 결과로 돌려 사용자가 거른다.
- 오타는 띄어 쓴 낱말의 첫 글자부터, 낱말 안에서만 본다. 그래서 `정류장 어디예요`(장어≈장터), `장례식장`(식장≈시장)을 시장으로 잡지 않는 대신, 띄어쓰기 없이 붙여 쓴 오타(`병원이랑시잔`)는 놓친다.
- 정확히 맞는 표현 밖의 오타도 본다(`병원이랑 시잔` → 병원·시장, 확인 필요). 2026-11-06 변경, 이전에는 병원만 돌려줬다.
- 2글자 미만 표현(`장`)은 검색어로 쓰지 않는다. 다만 띄어 쓴 낱말 전체가 `장`·`장에`·`장엘`·`장으로`·`장에서`이면 시장으로 추정하고 확인을 요청한다(`장에 가요`). 붙여 쓴 `정류장에`·`주차장에`는 해당하지 않는다.
