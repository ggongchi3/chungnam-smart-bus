# 목적지 표현 해석 — 규칙 기반 기준선

`interpreter.py`의 `interpret(payload)`가 자연어 목적지 표현을 등록 후보 ID에 연결한다. 학습 모델이 아니며 외부 호출이 없다. 입출력은 [contracts/README.md](../contracts/README.md) 1절을 따른다.

## 규칙

1. **정규화**: NFKC, 소문자, 한글·영숫자 외 기호 제거, 공백 정리 후 공백을 없앤 문자열로 비교한다.
2. **검색어 만들기**: 후보마다 이름·별칭 전체(`시연병원`), 합성 접두어 `시연`을 뺀 핵심어(`병원`, `큰병원`), 분류 표현(`CATEGORY_TERMS`)을 검색어로 만든다. 분류 표현은 핵심어에 그 분류어가 들어 있는 후보 **전체**에 연결한다.
3. **더 구체적인 표현 우선**: 입력에서 찾은 표현이 더 긴 표현의 범위 안에 있으면 버린다. `큰 병원`에서는 `큰병원`만 남고 그 안의 `병원`은 버린다.
4. **판정**: 남은 후보가 1개면 `matched`, 여러 개면 `needs_confirmation`, 없으면 `no_match`다. 어느 경우든 사용자가 후보를 확인하고 고른다.

## 분류 표현

| 분류어 | 연결하는 표현 |
| --- | --- |
| 병원 | 병원, 종합병원, 대학병원 |
| 시장 | 시장, 전통시장, 재래시장, 장터 |
| 터미널 | 터미널, 버스터미널, 시외버스터미널, 고속버스터미널 |

`의원`·`보건소`처럼 다른 종류의 장소일 수 있는 표현은 넣지 않았다. 표현을 추가할 때는 [evaluation/cases.json](../evaluation/cases.json)에 사례를 함께 추가한다.

## 알려진 한계

- 부정 표현(`병원 말고 시장`)을 이해하지 못한다. 두 후보를 모두 반환해 사용자가 고르게 한다.
- 오타·초성·발음 변형(`벙원`)은 연결하지 않는다.
- 2글자 미만 표현은 검색어로 쓰지 않는다.
