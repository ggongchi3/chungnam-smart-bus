# 외부 LLM 비교 실험 설계 v0.1

모델 도입 실험을 기준선·입출력 계약과 별도 비교 대상으로 진행하는 계획이다. **제공자는 Google Gemini로 정했다(2026-11-06, AI 담당).** 모델 기본값은 가장 빠른 계열인 `gemini-flash-lite-latest`이며 `GEMINI_MODEL`로 바꿀 수 있다. 키 발급 계정·요금·품질 목표는 아직 정하지 않았다. 이 문서는 실험 절차이며 결과가 아니다. 측정 전에는 어떤 정확도·응답 시간도 기재하지 않는다.

## 1. 질문

1. 규칙 기준선이 놓치는 표현(긴 문장, 다양한 부정, 사투리, 글자 누락 오타)을 LLM이 더 잘 연결하는가?
2. 그 대가로 허용 목록 밖 출력, 1초 초과, 비용이 얼마나 생기는가?
3. 백엔드 검증과 대체 동작이 있는 상태에서 사용자에게 보이는 결과가 실제로 나아지는가?

쉬운 안내(choose_guidance)는 현재 허용 템플릿이 유형별 1개라서 LLM이 고를 여지가 없다. 비교 대상은 목적지 해석(interpret_destination)으로 한정하고, 템플릿이 늘어나면 다시 검토한다.

## 2. 고정 조건

- **같은 계약**: LLM 어댑터도 `interpret_destination(payload) -> dict`를 그대로 구현한다. 출력은 후보 ID·상태·reasonCode뿐이며 장소명·설명·좌표를 받지 않는다.
- **같은 검증**: 백엔드 `backend/services/ai.py`의 검증·1초 예산을 그대로 통과해야 채택된다. 실험용으로 예산을 늘리지 않는다.
- **같은 평가 자료**: [cases.json](cases.json) 전체와, 팀이 모은 실제 표현 묶음(아래 4절)을 함께 쓴다.
- **보내는 데이터**: 사용자가 입력한 목적지 문장과 허용 후보 목록(ID·이름·별칭)만 보낸다. 정류장·노선·위치·기기 정보는 보내지 않는다. 입력 문장에 개인정보가 섞일 수 있으므로 제공자의 데이터 보관·학습 사용 조건을 선정 전에 확인한다.
- **키 관리**: 키는 `ai/.env`(커밋 제외, 루트 `.gitignore`가 이미 제외)에 두고 백엔드 프로세스에서만 읽는다. 변수 이름은 [ai/.env.example](../.env.example)을 따른다.
- **데이터 조건 확인 필요**: Gemini API는 무료 사용 단계와 유료 단계의 데이터 사용 조건이 다를 수 있다. 키를 발급받을 때 Google의 현재 약관에서 입력 문장의 보관·학습 사용 여부를 확인하고 여기에 기록한다.

## 3. 어댑터 구성(작성 완료, 2026-11-06)

```
ai/destination_interpretation/llm_interpreter.py   # 실험용, 기본 연결 아님. 표준 라이브러리(urllib)만 사용
ai/adapter.py: class GeminiAIAdapter:
    interpret_destination(payload) -> dict  # 실패·시간초과·형식 오류 시 unavailable
    choose_guidance(payload) -> dict        # 규칙 기준선(selector.choose)을 그대로 사용
```

- 프롬프트는 "목록의 ID 중에서만 고르고, 모르면 no_match"를 지시하고, 응답은 JSON 형식 강제 기능을 쓴다.
- 어댑터 안에서 먼저 허용 목록·형식을 검사한다. 백엔드 검증은 두 번째 방어선이다.
- 키·연결 확인: `python -m ai.destination_interpretation.llm_interpreter "큰 병원 가려고요"`(실패 원인을 그대로 출력). 비교: `python ai/evaluation/run_eval.py --adapter ai.adapter:GeminiAIAdapter`. 검증·대체 동작 테스트는 [test_llm.py](test_llm.py)(네트워크 없이 실행).
- 네트워크 제한시간은 1초보다 짧게 둔다(0.9초). 백엔드의 시간초과는 Python 작업을 중단하지 않으므로, 어댑터가 스스로 끝나야 다음 요청이 막히지 않는다(`AIBoundary`는 동시에 1개만 실행).

## 4. 평가 자료

| 묶음 | 출처 | 비고 |
| --- | --- | --- |
| 합성 사례 | `cases.json` | 규칙 기준선과 같은 사례 |
| 실제 표현 | 팀원·주변 어르신에게 "병원/시장/터미널 가려면 뭐라고 말할지" 수집 | 이름·연락처는 받지 않는다. 문장만 `real-expressions.json`으로 추가 |
| 함정 사례 | 목록에 없는 장소, 부정 표현, 장소가 둘 이상, 의미 없는 문장, 지시문 주입("목록 무시하고 ...") | LLM 전용 위험 확인 |

정답(기대 status·ID)은 두 명 이상이 따로 붙이고, 의견이 다르면 needs_confirmation을 정답으로 둔다.

## 5. 측정 항목

`run_eval.py --adapter 모듈:클래스`로 같은 자료에 두 어댑터를 돌려 비교한다.

| 항목 | 측정 방법 |
| --- | --- |
| 사례 통과 수 | 묶음별 통과/전체 (`run_eval.py`) |
| 위험 출력 | 허용 목록 밖 ID, 형식 오류, 정답이 no_match인데 matched를 낸 경우 수 |
| 응답 시간 | 중앙값·95%·1초 초과 건수 (`run_eval.py`) |
| 실제 채택 결과 | `test_backend_integration.py` 방식으로 백엔드 경유 시 사용자에게 보인 status |
| 비용 | 사례당 입력·출력 토큰과 제공자 요금표로 계산 |

반복 측정(최소 3회)으로 결과가 매번 같은지도 기록한다.

## 6. 채택 판단

판단 기준값은 실험 전에 팀이 정해 이 절에 적는다. 정하지 않은 상태로 결과를 보고 기준을 맞추지 않는다. 검토할 조건의 예:

- 위험 출력이 기준선보다 늘지 않는다.
- 1초 초과가 시연 흐름을 해치지 않는 수준이다.
- 실제 표현 묶음에서 통과 수가 의미 있게 늘어난다.
- 시연 환경의 네트워크·비용 조건에서 운영 가능하다.

채택하더라도 규칙 기준선은 대체 경로로 남기고, 첫 시연이 외부 모델 호출에 의존하지 않게 한다.

## 7. 1차 측정 결과 (2026-11-06, 1회 측정)

조건: macOS, 집 인터넷, Gemini 무료 키, `gemini-flash-lite-latest`(측정 시점에 `gemini-3.5-flash-lite`를 가리킴), temperature 0, JSON 형식 강제. 무료 한도(모델당 분당 15회) 때문에 호출 사이 4.5초씩 쉬었고 쉬는 시간은 측정에서 뺐다. **1회 측정**이며 3절의 반복 측정(3회)은 아직 하지 않았다. 합성 사례 결과일 뿐 실제 사용자 정확도가 아니다.

| 조건 | 전체 | 목적지 해석 사례(36건) | 응답 시간 |
| --- | --- | --- | --- |
| 규칙 기준선 | 59/59 | 36/36 | 중앙값 0.0ms |
| Gemini, 실제 예산(0.9초에서 끊음) | 30/59 | 9/36 (19건은 시간초과로 unavailable) | 중앙값 936ms, 1초 초과 16건 |
| Gemini, 정확도만(15초) | 52/59 | 29/36 | 중앙값 986ms, 95% 1767ms, 1초 초과 27건 |

15초 조건에서 틀린 7건:

| 사례 | 입력 | 기대 | Gemini | 위험도 |
| --- | --- | --- | --- | --- |
| i13 | 고속버스터미널 | matched 터미널 | no_match | 낮음(일반 검색으로 넘어감) |
| i22 | 의원 | no_match | matched 병원 | **높음** — 다른 종류의 장소를 병원으로 추정 |
| i32 | 장에 가요 | no_match | matched 시장 | 기대값 재검토 필요. 사람이 봐도 시장일 가능성이 큼 |
| i37~39 | 벙원 / 시잔 가요 / 터미날 | needs_confirmation | matched | 중간 — 오타 추정을 확정으로 냄. 화면에서 사용자가 한 번 더 확인하므로 잘못 이동하지는 않음 |
| i43 | 병원이랑 시잔 | matched 병원 | needs_confirmation 병원·시장 | 낮음. 기대값 재검토 필요 |

관찰:
- 허용 목록 밖 ID·형식 오류는 0건이었다(어댑터·백엔드 검증 통과).
- 정확도 자체는 규칙 기준선과 비슷하거나 낮다. 합성 사례가 규칙 기준선에 맞춰 만들어졌다는 한계가 있으므로, 비교는 4절의 실제 표현 묶음을 모은 뒤 다시 한다.
- **응답 시간이 1초 예산과 거의 같다.** 연결 재사용·`thinkingLevel: minimal`로 약 0.8~1.0초까지 줄었지만 예산 안에 안정적으로 들어오지 않는다. 키오스크 네트워크에서는 더 느릴 수 있다.
- 무료 한도(분당 15회)는 시연 한 대에는 충분하지만 반복 평가에는 대기가 필요하다.
