# 외부 LLM 비교 실험 설계 v0.1

개발 기준안 6절의 "모델 도입 실험은 기준선·입출력 계약을 대체하지 않고 별도 비교 대상으로 진행한다"를 구체화한 계획이다. 외부 LLM 제공자·모델·키·요금·품질 목표는 아직 정하지 않았다. 이 문서는 실험 절차이며 결과가 아니다. 측정 전에는 어떤 정확도·응답 시간도 기재하지 않는다.

## 1. 질문

1. 규칙 기준선이 놓치는 표현(긴 문장, 다양한 부정, 사투리, 글자 누락 오타)을 LLM이 더 잘 연결하는가?
2. 그 대가로 허용 목록 밖 출력, 1초 초과, 비용이 얼마나 생기는가?
3. 백엔드 검증과 대체 동작이 있는 상태에서 사용자에게 보이는 결과가 실제로 나아지는가?

쉬운 안내(choose_guidance)는 현재 허용 템플릿이 유형별 1개라서 LLM이 고를 여지가 없다. 비교 대상은 목적지 해석(interpret_destination)으로 한정하고, 템플릿이 늘어나면 다시 검토한다.

## 2. 고정 조건

- **같은 계약**: LLM 어댑터도 `interpret_destination(payload) -> dict`를 그대로 구현한다. 출력은 후보 ID·상태·reasonCode뿐이며 장소명·설명·좌표를 받지 않는다.
- **같은 검증**: 백엔드 `backend/services/ai.py`의 검증·1초 예산을 그대로 통과해야 채택된다. 실험용으로 예산을 늘리지 않는다.
- **같은 평가 자료**: [cases.json](cases.json) 전체와, 팀이 모은 실제 표현 묶음(아래 4절)을 함께 쓴다.
- **보내는 데이터**: 사용자가 입력한 목적지 문장과 허용 후보 목록(ID·이름·별칭)만 보낸다. 정류장·노선·위치·기기 정보는 보내지 않는다. 입력 문장에 개인정보가 섞일 수 있으므로 제공자의 데이터 보관·학습 사용 조건을 선정 전에 확인한다.
- **키 관리**: 키는 `ai/.env`(커밋 제외, 루트 `.gitignore`가 이미 제외)에 두고 백엔드 프로세스에서만 읽는다. 변수 이름만 적은 `ai/.env.example`은 제공자 선정 후 만든다.

## 3. 어댑터 구성(제공자 선정 후 작성)

```
ai/destination-interpretation/llm_interpreter.py   # 실험용, 기본 연결 아님
class LLMAIAdapter:
    interpret_destination(payload) -> dict  # 실패·시간초과·형식 오류 시 unavailable
    choose_guidance(payload) -> dict        # 규칙 기준선(selector.choose)을 그대로 사용
```

- 프롬프트는 "목록의 ID 중에서만 고르고, 모르면 no_match"를 지시하고, 응답은 JSON 형식 강제 기능을 쓴다.
- 어댑터 안에서 먼저 허용 목록·형식을 검사한다. 백엔드 검증은 두 번째 방어선이다.
- 네트워크 제한시간은 1초보다 짧게 둔다. 백엔드의 시간초과는 Python 작업을 중단하지 않으므로, 어댑터가 스스로 끝나야 다음 요청이 막히지 않는다(`AIBoundary`는 동시에 1개만 실행).

## 4. 평가 자료

| 묶음 | 출처 | 비고 |
| --- | --- | --- |
| 합성 사례 | `cases.json` | 규칙 기준선과 같은 사례 |
| 실제 표현 | 팀원·주변 어르신에게 "병원/시장/터미널 가려면 뭐라고 말할지" 수집 | 이름·연락처는 받지 않는다. 문장만 `real-expressions.json`으로 추가 |
| 함정 사례 | 목록에 없는 장소, 부정 표현, 장소가 둘 이상, 의미 없는 문장, 지시문 주입("목록 무시하고 ...") | LLM 전용 위험 확인 |

정답(기대 status·ID)은 두 명 이상이 따로 붙이고, 의견이 다르면 needs_confirmation을 정답으로 둔다.

## 5. 측정 항목

`run_eval.py --adapter 모듈:클래스`로 같은 자료에 두 어댑터를 돌려 비교한다.

| 항목 | 측정 방법 |
| --- | --- |
| 사례 통과 수 | 묶음별 통과/전체 (`run_eval.py`) |
| 위험 출력 | 허용 목록 밖 ID, 형식 오류, 정답이 no_match인데 matched를 낸 경우 수 |
| 응답 시간 | 중앙값·95%·1초 초과 건수 (`run_eval.py`) |
| 실제 채택 결과 | `test_backend_integration.py` 방식으로 백엔드 경유 시 사용자에게 보인 status |
| 비용 | 사례당 입력·출력 토큰과 제공자 요금표로 계산 |

반복 측정(최소 3회)으로 결과가 매번 같은지도 기록한다.

## 6. 채택 판단

판단 기준값은 실험 전에 팀이 정해 이 절에 적는다. 정하지 않은 상태로 결과를 보고 기준을 맞추지 않는다. 검토할 조건의 예:

- 위험 출력이 기준선보다 늘지 않는다.
- 1초 초과가 시연 흐름을 해치지 않는 수준이다.
- 실제 표현 묶음에서 통과 수가 의미 있게 늘어난다.
- 시연 환경의 네트워크·비용 조건에서 운영 가능하다.

채택하더라도 규칙 기준선은 대체 경로로 남기고, 첫 시연이 외부 모델 호출에 의존하지 않게 한다.
