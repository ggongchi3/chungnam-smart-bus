# 목적지 해석 결과별 화면·음성 문구 검토안 v0.1

프론트엔드 A(목적지 검색)·B(음성)·디자인 검토용 초안이다. 확정 문구가 아니며 디자인의 용어·문구 기준을 따른다. `{name}`은 백엔드가 준 후보의 `name`이다. 모든 화면에 `시연 데이터 · 실제 운행 정보 아님` 표시는 별도로 유지한다.

## 원칙

- 사용자에게 `AI`, `인식 실패`, `오류` 같은 내부 상태를 보여 주지 않는다. 할 수 있는 다음 행동 하나를 안내한다.
- 어떤 결과든 사용자가 후보를 직접 눌러 확정한다. `matched`도 자동으로 다음 화면으로 넘기지 않는다.
- 일반 검색·주요 장소 버튼은 항상 같은 자리에 남긴다. AI 결과는 그 위에 덧붙는 보조 안내다.
- 한 화면에 한 질문. 버튼은 아이콘과 글자를 함께 쓴다.

## 상태별 문구

| 공개 status | 화면 제목 | 본문 | 버튼 | 음성 안내 |
| --- | --- | --- | --- | --- |
| `matched` | 이곳이 맞나요? | {name} | [✓ 네, 여기로 갈게요] [✕ 다른 곳 찾기] | "{name}이 맞으면 '네'를 눌러 주세요." |
| `needs_confirmation`(후보 여러 개) | 어디로 가시나요? | 아래에서 가실 곳을 골라 주세요. | 후보마다 [{name}] + [✕ 다른 곳 찾기] | "가실 곳을 화면에서 골라 주세요." |
| `needs_confirmation`(후보 1개·오타 추정) | 이곳을 찾으셨나요? | {name} | [✓ 네, 여기로 갈게요] [✕ 다른 곳 찾기] | "{name}을 찾으셨으면 '네'를 눌러 주세요." |
| `no_match` | 찾는 곳이 목록에 없어요 | 아래 주요 장소에서 고르거나 다시 입력해 주세요. | 주요 장소 버튼 + [다시 입력] | "주요 장소 버튼에서 골라 주세요." |
| `unavailable` | (제목 없이 일반 검색 화면 유지) | 아래 주요 장소에서 골라 주세요. | 주요 장소 버튼 + 일반 검색 | 별도 안내 없음 |

- `unavailable`은 시간초과·오류를 포함한다. 사용자의 잘못처럼 보이지 않도록 실패 문구 없이 일반 검색 흐름을 그대로 보여 준다.
- 먼저 `status`에 따라 화면을 분기하고, `needs_confirmation` 안에서 후보 1개와 여러 개를 구분하려면 `candidates.length`를 쓴다. 후보가 1개라는 이유로 `matched`로 바꾸지 않는다. `reasonCode`는 [계약](README.md)의 네 값으로 통일했으며 화면 동작의 기준은 `status`다.
- 조사 `이/가`, `을/를`은 이름 끝 받침에 맞춰야 한다. 프론트엔드에서 처리하거나 조사가 필요 없는 문장으로 바꾼다(예: "{name}, 맞으면 '네'를 눌러 주세요").

## 쉬운 안내(easy_guidance) 대체

`mode`가 `ai_assisted`든 `template_fallback`이든 화면·음성·인쇄의 문장은 같은 서버 문장이다. 사용자에게 모드 차이를 표시하지 않는다. 개발자 확인용으로만 로그에 남긴다.

## 키오스크 기준 (디자인 `design/kiosk-concept/`, 2026-11-03)

- 화면은 세로형 260×460mm다. 후보 여러 개는 세로로 쌓고, 버튼 두 개([✓ 네, 여기로 갈게요] [✕ 다른 곳 찾기])도 가로로 좁으면 세로 배치를 우선 검토한다.
- 화면 아래 안내표 출력구와 스피커가 있다. 안내표 용지는 디자인 Print Guide(`design/guidelines/Print Guide`, 2026-11-05) 기준 **감열지 80mm, 인쇄 폭 68mm, 흑백, Pretendard**다.
  - 68mm에 한글은 8pt 기준 한 줄 약 24자, 10pt 기준 약 19자다(글자 폭 1em으로 어림). `bus.basic` 한 문장(합성 예시 약 70자)은 10pt로 4줄이 되므로, 인쇄물은 문장을 그대로 넣지 않고 출력물 구조(1. 여기서 타세요 → 버스 번호 → 이동 정류장 수 → 2. 여기서 내리세요)대로 나눈다.
  - 이 구조는 proposal `bus.split`(타기·내리기 두 줄)과 같은 방향이다. 인쇄용 안은 `bus.print`로 기록했다.
- 스피커가 있으므로 위 음성 안내 문구는 화면 문구와 함께 실제 길이로 읽어 보고 정한다.

## 검토 요청

- 디자인: 제목·버튼 문구 길이와 아이콘, 큰 글씨에서 줄바꿈. 안내표 용지 폭은 Print Guide로 확정(80mm). `bus.split`·`bus.print` 승격 검토.
- 백엔드: `bus.print`에 필요한 운행 방향(`direction`)과 하차 직전 정류장(`previousStation`) 데이터 제공 여부.
- A: PR #6에서는 상태별 분기 화면을 구현했다. 현재 통합 앱의 `frontend/src/app/App.tsx`는 일반 검색 결과가 비면 AI를 호출하고 반환된 후보를 결과 목록에 표시한다.
- B: 음성 문구의 길이, 화면 문구와 다르게 읽어도 되는지.
