# 충청남도 스마트 버스정류장 플랫폼

`chungnam-smart-bus`는 현재 정류장에서 목적지까지의 버스 이용 방법을 쉽게 확인하고, 종이 이동 안내표로 가져갈 수 있도록 기획한 웹 기반 키오스크 시제품 프로젝트다. 사용자 제공 기획 사진 4장과 이번 요청을 요구사항의 기준으로 삼는다.

현재 저장소에는 합성 데이터용 FastAPI 백엔드와 규칙 기반 AI 어댑터가 구현되어 있다. 기본 서버는 목적지 표현 해석과 안내 템플릿 선택을 연결하며 외부 모델·네트워크를 호출하지 않는다. 설치·실행은 [백엔드 안내](backend/README.md), AI 동작과 계약은 [AI 안내](ai/README.md)를 따른다. 프론트엔드·디자인은 자리 표시자이며 실제 교통 API는 연결되지 않았다.

## 핵심 기능과 초기 범위

| 기능 | 브라우저 시제품에서 구현할 내용 |
| --- | --- |
| 목적지 중심 노선 안내 | 현재 정류장 표시, 목적지 검색, 병원·시장·터미널 등 주요 장소 선택, 이용 가능한 경로 선택 |
| 실시간 운행 정보 | 도착 예정 정보, 운행 현황, 시간표 변경·결행·우회 안내, 항목별 최종 갱신 시각과 확인 불가 상태 표시 |
| 개인 맞춤형 이동 안내표 | 승차 버스, 승차·하차 정류장, 이동할 정류장 수, 도보·환승 안내와 인쇄용 화면 |
| 고령층을 고려한 UI | 큰 글씨와 버튼, 높은 명도 대비, 아이콘과 글자 병기, 간결한 화면, 음성 안내 재생·중지 UI |

출력은 브라우저 인쇄와 인쇄 미리보기를 사용하도록 계획한다. 초기 출력물은 일반 용지 기준으로 검토하며 정확한 용지 크기와 여백은 미정이다. 전용 영수증 프린터, 프린터 제어·출력 완료 감지, 실제 키오스크 장비 연결과 현장 설치는 확장 과제다.

외부 데이터 제공기관과 지원 범위는 확인 전이다. 초기 화면·연동 시연은 실제 운행과 무관한 합성 시연 데이터로 진행할 수 있다. 이때 화면과 인쇄물에 반드시 `시연 데이터 · 실제 운행 정보 아님`을 표시한다. 시제품 구현 계획이며, 현재 폴더에 시연 기능이 구현되어 있다는 뜻은 아니다.

## 사진의 요구사항과 추가 제안 구분

- 사진과 요청에 포함된 기능: 목적지 중심 안내, 실시간 정보와 변경 안내, 종이 안내표, 고령층 UI 및 음성 안내.
- 추가 제안 — AI: 자연어 목적지 표현을 등록된 목적지 후보에 연결하고, 검증된 경로의 쉬운 한국어 안내 표현을 선택한다. AI가 노선·정류장·환승 가능 여부·도착 시각을 생성하거나 결정하지 않는다.
- 추가 제안 — 시제품 구현 방식: 현재 정류장을 시연 설정에서 선택하고, 데이터 제공자와 분리된 연동 계층 및 시연 데이터를 사용한다. 브라우저 음성 합성 등을 포함한 음성 기술은 미정이다. 음성 입력은 초기 범위에 포함하지 않는다.
- 선택 확장: 디자인 담당의 키오스크 외형 콘셉트. 실제 장비 구현과는 구분한다.
- 사진의 기대 효과는 기획상 목표다. 인구 통계, 데이터 제공 범위, 운영 효과를 검증된 사실로 인용하지 않는다. 확인 항목은 [데이터 출처 문서](docs/data-sources.md)에 기록한다.

## 정확히 5명의 역할

| 담당 | 핵심 책임 | 주 담당 영역 |
| --- | --- | --- |
| ① 백엔드 1명 | 교통 데이터 모델·연동, 경로 계산/검증, 서비스 API, AI 중계, 공통 계약 | `backend/`, 공통 계약 문서 |
| ② 프론트엔드 A 1명 | 시작 화면, 현재 정류장, 목적지 검색, 경로 선택, 공통 화면 틀·UI·API 클라이언트 | `frontend/src/app/`, 검색·선택 기능, 공통 영역 |
| ③ 프론트엔드 B 1명 | 상세 이동 안내, 실시간 정보, 갱신 시각, 인쇄, 음성 안내 UI | `frontend/src/features/`의 안내·실시간·출력·음성 기능 |
| ④ AI 1명 | 추가 제안인 목적지 표현 해석·쉬운 안내 표현, 입출력 계약, 실패 처리와 평가 | `ai/` |
| ⑤ 디자인 1명 | 사용자 흐름, 와이어프레임, 화면·컴포넌트 기준, 에셋, 종이 안내표 | `design/` |

프론트엔드 A·B는 하나의 앱을 기능별로 나누어 개발한다. 두 앱을 만들지 않는다. 접근성은 두 사람 모두의 구현·검토 기준이다. 역할별 입력·산출물·협업 경계와 공통 항목 대표 관리자는 [roles.md](docs/roles.md)를 따른다.

## 폴더 안내

| 폴더 | 목적 |
| --- | --- |
| `backend/` | API, 비즈니스 로직, 데이터 모델, 외부 데이터 연동 |
| `frontend/` | 단일 프론트엔드 앱의 설정·화면·기능과 공통 UI/API 클라이언트 |
| `ai/` | 목적지 해석, 쉬운 안내 표현, 입출력 형식, 평가 자료 |
| `design/` | 와이어프레임, 시안, 에셋, 디자인 기준, 출력물, 선택 외형 콘셉트 |
| `docs/` | 역할, 내부 API 초안, 출처 확인, 전체 구조, 초기 생성 검증 기록 |

`frontend/src/features/destination-search/`, `route-selection/`은 A가 담당한다. `journey-guide/`, `live-info/`, `print-guide/`, `voice-guide/`는 B가 담당한다. 전체 파일 트리와 각 폴더의 목적은 [structure.md](docs/structure.md)에 있다.

## 공통 데이터와 책임

검색·선택에서 상세 안내로 이동할 때 `originStationId`, `destinationId`, `routeSearchId`, `routeOptionId`, `routeSnapshotVersion`, `dataMode`를 전달하도록 제안한다. B는 이 식별자로 백엔드의 경로 상세와 최신 운행 정보를 조회한다. 인수인계 객체 자체를 교통 사실의 근거로 삼지 않는다.

필드의 의미, 요청·응답 예시, 변경·만료·실패 처리는 [api-contract.md](docs/api-contract.md)에 정의한다. 이 문서는 우리 서비스 내부 설계 초안이며 외부 제공기관의 API 명세가 아니다. 사실 데이터와 시간의 기준은 백엔드가 관리하고, AI는 등록된 ID와 허용된 안내 표현만 반환한다.

## 개발 시작 순서

1. 5명 모두 역할·내부 API 초안·출처 확인 문서를 읽고 화면 흐름과 시연 범위를 합의한다.
2. 백엔드가 정류장·목적지·노선·경유 순서·경로 구간의 공통 모델과 합성 시연 시나리오를 정리한다. 디자인이 화면 흐름과 출력물 초안을 병행한다.
3. 언어·프레임워크·DB·빌드 도구·음성 기술·인쇄 용지를 합의하고, 확정된 설정과 실제로 검증한 설치/실행 방법을 이 README에 추가한다. 현재는 설치·실행 명령이 없다.
4. A가 하나의 앱과 공통 UI/API 클라이언트를 준비한다. B는 합의한 인수인계 객체와 동일한 시연 데이터로 상세·출력 화면을 구현한다.
5. 백엔드는 계약에 맞춘 API를 구현한다. AI 담당은 목적지 후보 ID 제한, 안내 템플릿 계약, 실패 시 대체 동작을 구현한다. 시연 데이터 연동 이후 실제 데이터 연동 가능성을 확인한다.
6. 시작 → 목적지 선택 → 경로 선택 → 상세 안내 → 음성/인쇄 미리보기 흐름을 함께 확인한다. 변경·미수신·오래된 정보·AI 실패·검색 결과 없음도 점검한다.

## 초기 협업 규칙 — 추가 제안

- `main`을 통합 기준으로 삼고 작업별 브랜치와 PR을 사용한다. 예: `feat/backend-routes`, `feat/frontend-search`, `feat/frontend-print`, `feat/ai-destination`, `design/guide-layout`.
- 공통 파일을 바꿀 때 [대표 관리자](docs/roles.md)에게 검토를 요청한다. 대표 관리는 단독 수정 권한이나 별도 여섯 번째 역할을 뜻하지 않는다.
- API 변경은 문서와 영향받는 A/B/AI의 변경을 함께 검토한다. 프레임워크 확정 전에는 의미 없는 패키지 설정이나 CI 실행 명령을 추가하지 않는다.
- `.gitignore`는 여러 언어에서 흔히 생성되는 의존성·빌드·캐시·로컬 설정·비밀정보를 제외하도록 준비했다. 실제 기술 스택 확정 후 필요한 규칙을 조정한다. 비밀키와 개인정보는 커밋하지 않는다.
- `temp`는 확장자가 없는 일반 파일이며 Git에서 추적할 자리 표시자다. 해당 폴더에 실제 작업 파일을 추가하면 그 폴더의 `temp`를 삭제한다. 하위 폴더만 있는 상위 폴더에는 추가하지 않는다.

## 현재 준비 상태

초기 폴더·기본 문서·자리 표시자를 생성했다. 생성 결과 점검은 [verification.md](docs/verification.md)에 기록한다. 원격 저장소 생성, Git 커밋 및 업로드는 수행하지 않았다. 팀의 후속 개발과 별도 업로드 요청을 위한 구조가 준비된 상태다.
