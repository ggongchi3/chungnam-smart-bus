# 프론트엔드 B · 상세 이동 안내

현재 앱 진입점은 `JourneyGuidePreview`다. 기본 화면은 로컬 백엔드의 합성 환승 경로를 검색하고, 반환된 선택 식별자로 상세를 다시 조회한다. 실제 교통 API 연결이나 A의 목적지 확인 화면 구현을 뜻하지 않는다.

## 디자인 기준

`design/guidelines/Print Guide`와 직통·환승 JPG 시안을 기준으로 목적지 중앙 정렬, 승차 위치 → 버스 번호 → 이동 정류장 수 → 하차 위치 순서를 사용한다. 흑백, 얇은 테두리의 버스 영역, 회색 하차 영역과 큰 핵심 글자를 공유한다. 화면 본문은 24px, 버튼은 높이 64px 이상이다. Pretendard가 설치되어 있으면 사용하며, 없으면 맑은 고딕 등 시스템 서체로 표시한다.

운행 방향과 직전 정류장은 현재 상세 API에 없으므로 표시하지 않는다. 시안의 가상 정류장명·번호를 교통 사실로 복사하지 않는다. 도보 거리와 시간은 각각 null을 확인 불가로 표시한다.

80mm × 최소 180mm, 좌우 6mm·상하 8mm 여백의 흑백 인쇄 레이아웃을 구현했다. 내용에 따라 길이가 늘어난다. 감열지의 잉크 면적을 줄이기 위해 인쇄물의 하차 영역은 회색 채움 대신 검은 테두리를 사용한다. 실제 프린터의 용지·커팅 설정은 별도 확인이 필요하다.

## 구현한 B 기능

- 상세 안내: 버스·환승·도보 구간, 미확인 거리/시간, 서버 식별자·버전 검사.
- 실시간: 도착 예정·명시적 운행 상태·운행 변경을 각각 표시한다. 원천 갱신·서버 수집·서버 응답 시각을 구분하고 오래됨/갱신 상태 확인 불가를 표시한다. 도착 미수신은 결행으로, 변경 조회 실패는 변경 없음으로 바꾸지 않는다.
- 조회 제어: 상세 화면에서 30초 간격, 진행 중 요청 중복 방지, 화면 이탈/숨김 시 취소·중단, 복귀 시 즉시 조회한다. 요청별 5초 제한이며 GET 연결 실패/5xx만 1초 뒤 1회 재시도한다. POST와 4xx는 자동 재시도하지 않는다.
- 인쇄: `POST /print-guides`의 같은 버전 스냅샷만 사용한다. 도착 카운트다운을 넣지 않고 고정 도착 예정 시각과 생성 시각을 표시한다. 미리보기 후 실제 인쇄 대화상자를 열기 직전에 상세를 다시 조회해 만료/변경을 확인한다. 별도 iframe 문서를 인쇄하므로 개발 버튼과 앱 전체가 안내표에 섞이지 않는다. 대화상자 열기/닫기를 물리적 출력 성공으로 표시하지 않는다.
- 음성: `POST /easy-guidance`의 검증된 같은 구간 순서·문장을 화면의 '음성 안내 문장 보기'와 음성·인쇄에 사용한다. 한국어 음성을 우선 선택하고 사용자가 재생·중지한다. 화면 숨김·경로 변경·인쇄 미리보기 진입·화면 이탈 시 중지한다. 지원 불가/한국어 음성 없음/재생 실패 시 글 안내를 유지한다.

각 기능의 파일은 `../live-info/`, `../print-guide/`, `../voice-guide/`에 있다. `JourneyFeatures`가 상세 화면에 세 기능을 연결한다. API 연결 예시에서만 이 기능들이 활성화되며 정적인 화면 예시에는 표시하지 않는다.

## A 화면과 연결

`JourneyGuideScreen`에 `selection`과 `onReselect`를 전달한다. `selection`은 `originStationId`, `destinationId`, `routeSearchId`, `routeOptionId`, `routeSnapshotVersion`, `dataMode` 6개 필드를 사용한다. `onReselect`는 A의 경로 선택/검색 화면으로 돌아가는 처리다.

상세·실시간·음성·인쇄 응답의 식별자·버전·모드·구간을 확인한 뒤 사용한다. 버전 변경(409), 검색 만료(410), ID 누락/찾을 수 없음은 다시 선택하도록 안내한다. 핵심 자료 확인 불가(503)는 기존 안내·음성·인쇄를 중단하고 재시도하도록 안내한다. 도착만 미수신인 200 응답은 핵심 경로를 유지하며 확인 불가로 표시한다. 선택 변경이나 화면 이탈 시 요청을 취소하고 이전 응답이 화면을 덮지 않게 한다.

`journeyApi.ts`는 공통 API 클라이언트가 아직 없는 상태에서 사용하는 B 기능의 임시 연결 지점이다. A의 공통 클라이언트·타입이 준비되면 이 부분을 공통 import로 교체한다. 공통 폴더와 백엔드 코드는 수정하지 않았다. 기본 서버 주소는 `http://127.0.0.1:8000`이며 필요하면 Vite 환경변수 `VITE_API_BASE_URL`로 바꾼다.

`previewApi.ts`의 경로 검색은 개발 확인용으로만 사용한다. A의 실제 흐름에서는 사용자가 status에 맞는 목적지 확인과 경로 선택을 마친 뒤 선택 객체를 전달한다. 화면 아래 '개발 확인'을 펼치면 API 직통·환승 경로 또는 API를 사용하지 않는 화면 예시를 선택할 수 있다.

## 실행과 확인

프로젝트 루트에서 백엔드를 실행한다.

```powershell
backend/.venv/Scripts/python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

다른 터미널의 frontend 폴더에서 `npm run dev`로 화면을 연다. 아래 명령으로 빌드·코드 검사·API 검증을 실행한다.

```powershell
npm run build
npm run lint
$env:BUS_API_SMOKE='1'
node --test tests/journeyApi.test.mjs tests/b-features.test.mjs
```

API 검증은 Node 24의 내장 테스트 기능을 사용한다. 실제 서버 검증은 새 검색을 생성하며 기존 경로·시나리오를 수정하지 않는다. 백엔드 없이 경계 조건만 검사하려면 BUS_API_SMOKE를 설정하지 않고 테스트를 실행한다.

브라우저 검사는 `node tools/check-b-browser.mjs`다. 기존 Playwright 설치가 필요하며 프로젝트 의존성은 추가하지 않았다. 필요하면 `BUS_PLAYWRIGHT_PATH`에 설치된 Playwright의 `index.mjs`, `BUS_CHROME_PATH`에 Chrome 실행 경로를 지정한다. 개인 브라우저와 분리된 임시 프로필을 사용한다. 검사 결과·스크린샷·인쇄 HTML/PDF는 Git 제외 폴더 `frontend/qa.local/`에 저장된다. 음성 엔진과 실제 인쇄 대화상자는 모의 기능으로 동작 검증하므로 스피커 출력·물리 인쇄 성공을 증명하지 않는다. PDF 검사는 pypdf가 있는 Python으로 `python tools/check-print-pdf.py`를 실행한다.

## 사용자가 직접 확인할 항목

1. `http://localhost:5173/`에서 상세 아래에 버스 도착·운행 정보, 종이 안내표, 음성 안내가 표시되는지 확인한다. 기본 경로는 합성 환승 경로다. '개발 확인'을 펼쳐 API 직통 경로도 확인한다.
2. 새로고침과 30초 갱신을 확인한다. 정상 시연도 시간이 지나면 오래됨/도착 확인 불가가 되는 것이 맞다. 원천 시각을 최신처럼 다시 쓰지 않는다.
3. '인쇄 안내표 준비'를 누르고 80mm 미리보기의 승차·하차·환승·시연 표시·생성 시각을 확인한다. Esc 또는 '미리보기 닫기'로 돌아올 수 있다.
4. 감열 프린터에서 용지 폭 80mm, 배율 100%, 브라우저 머리글/바닥글 끄기를 확인하고 인쇄 대화상자를 연다. 실제 출력·긴 용지·줄바꿈·자동 커팅은 장비에서 확인한다. PDF 저장으로도 확인할 수 있다.
5. '안내 듣기'와 '중지'를 누르고 한국어 발음·음량·문장 순서를 확인한다. 음성이 없으면 기기의 한국어 음성 설치 상태를 확인한다. 자동 테스트는 실제 소리를 듣지 않는다.
6. 실제 경로를 선택해서 진입하는 전체 사용자 흐름은 A 화면과 연결한 후 함께 확인한다. 목적지 확인 status 분기는 A 영역이며 이 구현에서 변경하지 않았다.
